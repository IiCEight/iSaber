# Archive pagination — local review

The owner approved numbered pages after the previous “More articles” link replaced the first 20 articles with the final 15 and exposed an opaque cursor in the address bar. The implementation is local on `fix/archive-numbered-pagination`; it has not been pushed or deployed.

The reusable React pagination component follows the current Archive: indigo background, fine dividers, outlined circular page links, a filled pink current page, and rectangular Previous/Next controls. Disabled directions remain visible without being keyboard targets. Previous sits at the left edge, numbered pages stay centered, and Next sits at the right edge. The redundant “Page X of Y” line is omitted. Sorting sits beside the article count as flat text tabs: Written, Last updated, Published, and Best match during search. A pink underline identifies the active field. A separate text-and-arrow control reverses newest/oldest order, retaining that direction when switching fields. All controls are ordinary links and work without JavaScript; there is no dropdown or Apply step. Mobile uses labeled arrow controls with the same arrangement. Larger collections use a compact page window with ellipses.

- `/archive`: “1–10 of 35 articles”, items numbered 01–10, page 1 selected.
- `/archive?page=2`: “11–20 of 35 articles”, items numbered 11–20, page 2 selected.
- `/archive?page=4`: “31–35 of 35 articles”, items numbered 31–35, page 4 selected. Archive requests 10 items per page explicitly; the existing API default remains unchanged.
- Sorting defaults to Written, newest first for browsing and search. It offers newest/oldest ordering for Written date, Last updated, and Published date; search also offers Best match. Article row dates follow the selected date field (Best match uses publication dates). Sorting applies to the complete matching collection. Changing sort resets page 1, and the choice is stored in `sort=written`, `written_oldest`, `updated`, `updated_oldest`, `newest`, `oldest`, or `relevance` for shareable links.
- Search, sort, and category/tag/language conditions survive page changes. Editing or removing conditions resets page 1.
- Pagination links target the article collection, work without JavaScript, and support browser Back. Out-of-range pages resolve to the last available page.
- Old Archive cursor links return to the first page while preserving their conditions. Other cursor-based API clients and the separate Search page keep their existing behavior.

The API adds optional page-number requests and genuine filtered public totals, without a database migration. Private articles, drafts, and historical-only revisions are excluded from both totals and results. Numbered search uses two ordered scans within one database snapshot: the first counts matches (rank bands for Best match), the second selects the requested slice. Date sorting uses the selected date and ID consistently across browse and search. It retains at most one page of result summaries and keeps the existing search deadline/concurrency limit.

Local preview: <http://127.0.0.1:3001/archive>. It uses the real Go API and a disposable local database with a snapshot of 35 public article summaries. Article bodies are explicitly placeholders; owner data and production databases are untouched.
